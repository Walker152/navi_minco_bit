RoboMaster 2026 Sentry Behavior Tree - Phase 2 Task1. 任务背景 (Task Context)本项目为 RoboMaster 2026 赛季哨兵机器人智能决策系统。在第一阶段“一脑三躯”正交化架构的基础上，现需进行 Phase 2 (第二阶段) 逻辑迭代。本次迭代的核心目标是：引入云台手手动接管 (Manual Override)、受击避险机制 (Hit-and-Run)、动态热量管理、以及小陀螺 (Spin/Gyro) 智能调度。2. 架构强制约束 (Strict Architectural Constraints)在编写任何代码之前，必须严格遵守以下规范：通信与转换防线：所有来自外界（雷达、云台手、裁判系统）包含点位坐标的数据（position），在 ros_interface.cpp 中注入黑板前，必须强制进行坐标系转换（转换为 map 绝对坐标）。严禁将 Minimap 或原生地图坐标直接丢进黑板。状态解耦封装：像“血量下降后冷却 5 秒”这种带时序状态的逻辑，必须封装在 C++ 的 ConditionNode 中维护内部时间戳，绝对禁止在 XML 中用一堆 Timer 和 Inverter 节点拼凑，保持 XML 的极简与扁平。新增通信协议：所有对下位机的新增指令（control_mode, use_gyro_mode, gyro_vel）必须统一打包到 ros_interfaces::msg::Behavior 中，由 ros_interface.cpp 的 10Hz 定时器统一发给下位机。3. 参考文件目录 (Workspace Directory)请基于现有目录结构修改代码：消息定义包: src/ros_interfaces/msg/Behavior.msg (需新增字段)。BT 功能包: src/decision/bt_manager/include/bt_manager/blackboard.hpp (需新增状态变量)。src/ros_interface.cpp (需新增坐标转换与下发打包逻辑)。tree/*.xml (需重构相关分支)。src/condition/ & src/action/ (需新增对应的 C++ 节点)。4. 核心业务逻辑需求 (Core Business Logic)4.1 数据总线与通信升级 (Comm & Transform)坐标系统一化：在 ros_interface 接收到云台手指令坐标、雷达敌方/友方坐标时，调用 TransformUtils 将其转换至 map 系，然后再存入 Blackboard。下行数据扩展 (Behavior.msg)：新增 uint8 control_mode (0: AUTO, 1: MANUAL)。新增 bool use_gyro_mode。新增 float32 gyro_vel (小陀螺转速, rpm)。4.2 导航树更新 (Nav Tree - Chassis)最高优先级 (Priority 0): 云台手接管 (Manual Override)IF 接收到云台手指定坐标 -> 设 control_mode = MANUAL，打断所有自动决策，底盘前往该点。超时退出机制：IF 云台手坐标保持不变超过 T 秒 (如 3-5 秒) -> 自动恢复 control_mode = AUTO，退出接管状态。前哨站受击避险 (Outpost Hit-and-Run)修改原有的前哨站响应逻辑：新增血量监测。IF (正在前哨站模式 AND 自身血量突然下降) -> 立即退出前哨站模式。冷却机制：在此后直到“血量连续 5 秒未发生变化”且仍满足前哨站触发条件之前，禁止再次进入前哨站响应分支。4.3 云台树更新 (Gimbal Tree)同步前哨站避险：云台树的前哨站特定巡检模式，必须与 Nav Tree 保持同步的“血量下降强制退出及 5 秒冷却”约束。可以使用共享的黑板标志位或相同的 Condition 节点来保证行为一致。4.4 姿态树更新 (Stance Tree)默认姿态变更：兜底默认姿态由 MOVE 改为 DEFEND。移动姿态 (MOVE) 严格准入条件：IF (需要从己方防守区前往高地 [即过洞] OR 需要回家补给) AND (当前不在高地区域) -> 切换为 MOVE。攻击姿态 (ATTACK) 滞回与热量控制：IF (枪口当前热量 > 200) -> 强制切为 ATTACK 姿态（利于散热或迎敌）。IF (枪口当前热量 < 80) -> 退出因热量触发的 ATTACK 姿态，交由其他逻辑判定。IF (正在击打前哨站) -> 使用 ATTACK 姿态。小陀螺联动 (Gyro Control)：IF 当前姿态 == MOVE -> use_gyro_mode = false。ELSE (即 ATTACK, DEFEND 等) -> use_gyro_mode = true，并赋予合适的 gyro_vel 数值。这些变量需实时写入 Blackboard，由 ros_interface 发布。5. 任务执行流程 (Execution Workflow)请按以下步骤逐一输出代码与修改方案：[ ] Step 1: 消息与总线改造：修改 Behavior.msg，更新 blackboard.hpp 的默认值，重写 ros_interface.cpp 中的坐标系转换与 10Hz 定时器发布逻辑。[ ] Step 2: C++ 节点开发：- 编写 CheckManualOverride (含超时剥夺逻辑)。- 编写 CheckOutpostSafeResponse (含掉血监测与 5s 冷却时序逻辑)。- 编写 CheckMoveStanceCondition (空间拓扑判断)。- 编写 CheckHeatAttackCondition (滞回区间判断)。[ ] Step 3: XML 重构：分别更新 nav_tree.xml, gimbal_tree.xml, stance_tree.xml，将新节点完美无缝地插入现有的 ReactiveFallback 抢占流中。[ ] Step 4: 静态审查与说明：简要说明 C++ 中时间戳状态的管理方式，以及是如何保证云台手接管具备最高优先级的。
