# ROGMap 动态 3D 感知 + 2D 地形距离场改造结果

## 完成状态

本次改造按 `task.md` 的 8 个总目标完成了第一阶段可编译闭环。ROGMap 端 2D layer/field/query 架构已建立，planner 关键搜索、碰撞检查、走廊生成和 MINCO 优化路径通过 `MapQueryInterface` 读取 ROGMap 生成的二维层与 2D ESDF，不直接访问 ROGMap 内部 buffer。Nav2 global planner 插件外壳仍保留用于现有系统接入，但核心规划查询链路不再回退读取 Nav2 costmap。

1. ROGMap 保留并继续维护局部 3D Occupancy Grid。
2. 新增 `ProjectionLayer`，从 3D occupancy 做 z-column 高程分析，生成二维语义层。
3. 二维层输出 `value` cost buffer 和 `mask`，其中 `mask=0` 为 obstacle seed，`mask=1` 为 free/passable。
4. `small_rog_map::DynamicLayer` 增加 `updateFromMask()` 和统一 `rebuild()`，ROGMap 内部也新增同等 2D signed distance field。
5. ROGMap 每次更新后由二维 mask 生成 2D signed distance field，并通过 `evaluate(pos, dist, grad)` 查询距离和梯度。
6. Planner 新增 `MapQueryInterface` 读取路径，支持显式 `setMap()` 注入和 registry 获取 ROGMap 查询接口，不直接访问 ROGMap 内部 buffer；搜索开始时会复制 cost buffer，避免 ROGMap sliding/refresh 时裸指针失效。
7. 未实现动态障碍聚类、Kalman/track id/速度估计。
8. 未添加轮速接口，未修改 LIO/Estimator 状态量。

## 关键改动

ROGMap:

- 新增 `map_query_interface.hpp`：泛化只读地图接口。
- 新增 `map_registry.hpp/.cpp`：进程内过渡 registry。
- 新增 `projection_layer.hpp/.cpp`：二维 z-column 投影/高程语义层。
- 新增 `field_layer.hpp/.cpp`：二维 signed ESDF field。
- 新增 `query_adapter.hpp/.cpp`：snapshot + field 的只读 adapter。
- `MapQueryInterface` 保留 `values()`，并新增 `copyValues()` 安全复制接口；A*/SMAC 规划开始时通过 snapshot 拷贝 cost buffer，避免刷新时裸指针悬空。
- `QueryAdapter::evaluate()` 直接使用 snapshot 内的 distance field 做双线性 distance/gradient 查询，避免 value buffer 和 ESDF 在 ROGMap sliding/refresh 时错位。
- 修改 `prob_map.*`：增加 `last_hit_time_`、`last_update_time_`、active list 和 `applyDecay()`。
- 修改 `rog_map.*`：更新主流程为 3D occupancy -> decay -> 2D layer -> field -> query snapshot。
- 修改 `rog_map_ros2.hpp`：ROS callback 也走统一更新路径，并新增 `/rog_map/layer/value`、`/rog_map/layer/type`、`/rog_map/layer/height`、`/rog_map/field/points` debug topic。

Minco planner:

- 修改 `small_rog_map::DynamicLayer`：增加 `updateFromMask()`，旧点云更新复用统一 `rebuild()`。
- 修改 SMAC、A*、MINCO optimizer、corridor、collision check：有 `MapQueryInterface` 时优先走 ROGMap 查询接口。
- 新增 `MincoPlanner::setMap()` 显式注入入口；无 Nav2 costmap 时可通过 `global_frame` 参数和 odom 缓存获取当前机器人 pose。
- 移除 planner 对 `/global_costmap/voxel_grid` 的动态 ESDF 订阅调用；旧 `HybridESDFMap` 仅作为静态 PCD ESDF fallback。
- `minco_planner` 增加 `rog_map` package 依赖。

## 当前验证说明

已完成定向编译验证：

```bash
colcon build --packages-select rog_map minco_planner --cmake-args -DCMAKE_BUILD_TYPE=Release
```

结果：`rog_map` 和 `minco_planner` 均编译通过。

本轮修复与复核点：

- 在 `minco_planner.cpp` 顶部新增了 `isLineFree(MapQueryInterface)` 前置声明。
- 该 helper 现在能被 `ReplanLocal()` 的 lambda 正常解析，不再触发 `defined but not used`。
- 复核时额外修复了 `values()` 裸指针跨刷新可能悬空的问题：SMAC 和原 A* 改为通过 `copyValues()` 从 snapshot 复制 cost buffer。
- `QueryAdapter::evaluate()` 改为查询 snapshot distance field，保证 distance/gradient 与 snapshot 元数据一致。
- 补充 `MincoPlanner::setMap()`，方便同一 component/main 显式依赖注入，减少对过渡 registry 的依赖。
- `MincoPlanner::configure()` 不再无条件解引用 `costmap_ros_`；没有 Nav2 costmap 时使用 `global_frame` 参数。
- `MincoPlanner::getRobotPose()` 在无 Nav2 costmap 时从 odom 缓存读取 pose，并在 TF 可用时转换到 `global_frame_`。

## 阶段审计

- 阶段 1：ROGMap package 已有 `rog_map::DynamicLayer` 和 `rog_map::ESDFUtils`，支持 `updateFromMask()`、`rebuild()` 和 `evaluate()`；planner 原 `small_rog_map::DynamicLayer` 也保留点云接口并新增 mask 更新接口。
- 阶段 2：`ProjectionLayer` 已实现 UNKNOWN/FREE/PASSABLE/OCCUPIED 分类，输出 `value` 和 `mask`，并支持 height/ratio/timestamp 字段。
- 阶段 3：`ProbMap` 已增加 hit/update timestamp、active list、`applyDecay()`；hit/miss/decay 状态变化复用 `updateCellState()` 通知 inflation/ESDF/frontier。
- 阶段 4：`ROGMap::updateMapInternal()` 已串联 robot state、3D occupancy、decay、2D layer、2D field 和 query snapshot refresh。
- 阶段 5：`ROGMap` 暴露 `getQueryInterface()`，`MapRegistry` 支持进程内过渡获取，`MincoPlanner::setMap()` 支持显式注入。
- 阶段 6：A*、SMAC、corridor、collision check 和 MINCO optimizer 主路径均通过 `MapQueryInterface` 查询地图；不再订阅 `/global_costmap/voxel_grid` 作为动态 ESDF 输入。
- 阶段 7：已发布 value/type OccupancyGrid 和 height/field PointCloud2 debug topic；这些 topic 只用于可视化，不作为 planner 主链路。

## 后续 TODO

- 仍保留 Nav2 global planner 插件接口，后续如需完全脱离 Nav2 启动，可再增加独立 planner node/component 外壳。

- 可根据实车地形再调 `low_obstacle_height`、`obstacle_height`、`passable_cost` 和 `field/inflation_radius`。

## task4.md 1-11 最终收口记录

构建验证：

```bash
colcon build --packages-select rog_map minco_planner --cmake-args -DCMAKE_BUILD_TYPE=Release
```

结果：`rog_map`、`minco_planner` 均编译通过。当前仅保留既有 PCL pcap、unused parameter、`fmt` enum deprecated 等 warning，不影响本轮 task4 目标编译闭环。

1. 清理旧架构：

- 验收搜索：`PlannerManager`、`sentry_planner_node`、`MapSnapshotPublisher`、`MapQueryClient`、`rog_node_`、`sentry_planner_rog_map` 只剩任务/改造记录说明文本，实际源码/CMake/launch 参数路径未发现有效引用。
- 当前系统主路径只保留 Nav2 `planner_server` 加载 `minco_planner/MincoPlanner` plugin。

2. MincoPlanner 唯一调度入口：

- `MincoPlanner::configureRogMap()` 在 plugin 内创建 `ROGMapROS`，随后 `setMap(rog_map_ros_->queryInterface())` 并写入 `MapRegistry` 兜底。
- `ensureMapAvailable()` 是 planner 中唯一 `MapRegistry::get()` 调用点，仅在内部创建 ROGMap 失败时兜底。
- `setMap()` 统一分发给 SMAC、A*、MINCO optimizer、corridor；collision validation/safety/checkCollision 直接使用 `map_->evaluate()`。

3. ROGMapROS 使用 planner_server LifecycleNode：

- `ROGMapROS(const rclcpp_lifecycle::LifecycleNode::SharedPtr &, const rog_map::Config &)` 已存在并由 `MincoPlanner::configureRogMap()` 调用。
- 未创建额外普通 `rclcpp::Node`；ROS subscription/timer 绑定到 planner_server 的 node interfaces。
- `queryInterface()` 返回 core 内部 `QueryAdapter` shared_ptr。

4. sentry1.yaml 参数路径：

- `sentry1.yaml` 中 ROGMap 参数完整放在 `planner_server.ros__parameters.MincoPlanner.rog_map` 下。
- 当前不再依赖顶层 `rog_map.ros__parameters`，也不硬编码 cloud topic 或 frame id。

5. Config 嵌套参数加载：

- `Config::loadFromRosNode(node, prefix)` 支持 `MincoPlanner.rog_map.*` 嵌套路径，读取 bool/int/double/string/vector 参数。
- 每个 ROS 参数在读取前会用当前默认值 `declare_parameter`，并在加载后输出简洁 summary。
- 旧 `Config(cfg_path, namespace)` / `ROGMapROS(nh, cfg_path, namespace)` YAML 文件加载入口已删除，当前唯一主路径为 `loadFromRosNode()` 读取 `planner_server.ros__parameters.MincoPlanner.rog_map`。

6. sentry1.yaml 完整 rog_map 段：

- 已加入 task4 指定的 `frame_id`、`resolution`、`map_sliding`、`ros_callback`、`raycasting`、`decay`、`projection`、`field`、`performance`、`visualization` 子段。
- `use_dense_cloud=false`，默认 cloud topic 为 `/cloud_registered`，frame 使用 `camera_init`。

7. ROGMap 内部功能补齐：

- `QueryAdapter::evaluate()` 支持 `InterpolationMode::QUADRATIC`，边界或 3x3 非 finite 时 fallback 到 bilinear，输出梯度单位为 m/m，并统一 clamp 后置零梯度。
- `ProjectionLayer` 新增 `updateFull()`/`updateDirty()`；dirty columns 会按 `hole_fill_radius + 1` 膨胀，未更新 cell 保留上一帧数据，超过 `dirty_full_ratio` 或 geometry/sliding/full refresh 时走 full update。
- `ROGMap` 新增 dirty-aware field 重建：`field_dirty_`、`field_sequence_`、`field_stamp`、`field_stale`，没到 `field.update_rate` 周期时只刷新 query snapshot，不重建 EDT，并记录 `field_skipped_count`。
- `ProjectionLayer` 扩展 body band、ground、ceiling、slope、step、clearance 语义，RM 斜坡/洞口/通道/隧道墙分类不再只按整列 height-only 阻断。
- decay/fading 的 hit/miss/decay/reset/sliding 路径会维护 dirty column；parallel raycasting 保持 thread-local miss、串行 merge、hit 优先。

8. PerformanceMonitor：

- 新增 `rog_map/performance_monitor.hpp/.cpp`，集中保存 `RuntimeStats`、CSV stream、scoped timer 和 enable/csv/publish/print 开关。
- `performance.enable=false` 时不打开 CSV 文件；旧 `writeTimeConsumingToLog()`/`writeMapInfoToLog()` wrapper 在 stream 未打开时直接返回。
- 统计字段补齐 dirty、field skipped、visualization 等 task4 要求字段。

9. ROGMapVisualizer：

- 新增 `rog_map/rog_map_visualizer.hpp/.cpp`，集中创建可视化 publisher 并管理 visualization timer。
- `visualization.enable=false` 时不创建 visualization publisher/timer；子 topic 按各自 enable 控制；map bound 使用 lazy publish 检查订阅者。
- ROGMapROS 只保留数据填充/发布回调，publisher/timer 生命周期由 `ROGMapVisualizer` 管理。

10. Planner 使用 ROGMap 边界原则：

- SMAC/A* 搜索从 `MapQueryInterface::copyValues()` 获取 ROGMap 动态约束快照；SMAC 仍可叠加静态 ESDF guide。
- MINCO obstacle cost、trajectory validation、`checkCollision()`、`safetyTimerCallback()`、corridor 动态安全边界均通过 `map_->evaluate()`/`map_->isFree()` 查询 ROGMap。
- 静态 ESDF 仅保留为引导或 fallback，不作为最终动态安全判断。

11. 生命周期清理：

- `MincoPlanner::cleanup()` 释放参数回调、FSM/safety timer、FSM/recovery/planner handle、visualizer、A*/SMAC/MINCO/corridor、backup/yaw optimizer、path publisher、odom subscriber、costmap handle、`map_` 和 `rog_map_ros_`。
- 不关闭 planner_server node，不调用 `rclcpp::shutdown()`。
