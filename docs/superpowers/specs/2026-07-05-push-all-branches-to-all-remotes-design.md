# 全分支多远程推送脚本设计

## 目标

在仓库根目录提供一个 Bash 脚本，将当前仓库的全部本地分支推送到 Git 配置中定义的全部远程仓库。脚本必须保持远端历史安全，便于预览，并在部分远程仓库失败时给出完整汇总。

## 范围

- 动态读取 `git remote` 返回的全部远程仓库，不硬编码当前的远程仓库名称或地址。
- 使用 Git 原生 `git push <remote> --all` 语义推送全部本地分支。
- 支持 `--dry-run`，使用 Git 的 dry-run 能力预览每个远程仓库的推送结果。
- 支持可重复的 `--exclude <remote>` 参数，按名称精确排除一个或多个远程仓库；该参数可与 `--dry-run` 任意排序组合。
- 正常执行前列出本地分支和远程仓库，并要求用户明确确认。
- 逐个处理远程仓库；单个远程仓库失败时继续处理其余仓库。
- 最后汇总成功与失败的远程仓库；只要存在失败，脚本以非零状态退出。

## 非目标

- 不推送 tags、notes 或其他非分支 refs。
- 不删除远端独有分支，不使用 `--mirror` 或 `--prune`。
- 不使用 `--force` 或 `--force-with-lease`；non-fast-forward 必须由 Git 拒绝。
- 不获取、合并或改写远端分支，不修改本地分支及其 upstream。
- 不执行实际远程推送作为本次实现验证的一部分。

## 结构与数据流

新增一个位于仓库根目录的可执行 Bash 脚本。脚本首先确认当前目录属于 Git worktree，然后解析 `--dry-run` 和可重复的 `--exclude <remote>` 参数。随后分别通过 `git for-each-ref refs/heads/` 和 `git remote` 收集本地分支与远程仓库；本地分支或远程仓库集合为空时给出明确错误并退出。

脚本验证每个排除名称都对应已配置的 remote，再将 remote 划分为“将推送”和“已排除”两组。不存在的排除名称视为参数错误；排除全部 remote 时停止并报错。正常模式展示本地分支及两组 remote 后从标准输入读取确认，只有用户输入 `y` 或 `Y` 才开始推送。dry-run 模式不要求确认，因为它不会更新远端。对每个未排除 remote 调用一次 `git push [--dry-run] <remote> --all`，记录结果但不中断循环，最后输出摘要并据此决定退出状态。

## 错误处理

- 非 Git 仓库、未知参数、没有本地分支或没有 remote：推送前失败，退出码非零。
- `--exclude` 缺少名称、名称不存在或排除全部 remote：推送前失败，退出码非零。
- 用户取消：不调用 `git push`，正常退出并说明已取消。
- 认证失败、网络失败、权限不足或 non-fast-forward：保留 Git 的原始错误输出，继续尝试其他 remote，最终退出码非零。
- 分支名和 remote 名均按行读取并始终加引号，避免 shell 单词拆分。

## 测试设计

测试脚本使用临时目录创建一个源 Git 仓库和两个本地 bare remote，不访问当前配置的 Gitee/GitHub 地址。测试先于实现编写并验证失败，再以最小实现使其通过。覆盖：

1. `--dry-run` 不更新任何 bare remote。
2. 正常确认后将多个本地分支推送到两个 bare remote。
3. 用户拒绝确认时不推送。
4. 某个 remote 失败时仍处理后续 remote，最终返回非零状态。
5. 未知参数和缺少 remote 时返回非零状态。
6. 单个及多个 `--exclude` 可与 `--dry-run` 任意排序组合，并且被排除的 remote 不发生更新。
7. 排除名称不存在、缺少参数值或排除全部 remote 时返回非零状态，且不更新任何 remote。

测试只运行 shell 与 Git 命令，不触发项目编译、链接或代码生成。

## 安全边界

脚本不包含强推、远端删除或镜像操作。现有 ROS 2 源码、参数、launch、行为树及比赛验证逻辑均不修改。实现和验收期间不会连接或推送到当前真实远程仓库。
